# 極端なパスキー検討ペルソナ v1

行動の違いが見えるか調べるため、意図的に差を大きくした架空の 8 条件です。
実在ユーザーの分布や、人間を再現できることを示す定義ではありません。
既存の A、B、C と実験結果は変更しません。

## 4 つの対照ペア

- **知識 XK0 / XK1**：パスキー関連の専門用語を知らない人と、仕組みに詳しい人。
  `knowledge` を変えます。両方とも GitHub での設定は初めてで、操作経路は知りません。
- **経験 XE0 / XE1**：実利用ゼロの人と、他サービスで毎日使い 500 回以上の利用経験がある人。
  `serviceExperience` を変えます。記載する基本知識は同じで、GitHub 固有の利用経験は両方ありません。
- **優先順位 XP0 / XP1**：少ない手間で早く暫定判断したい人と、判断根拠への納得を強く求める人。
  `expectations` と `behavioralTendencies` を変えます。読了、回数、経路、完了や離脱は固定しません。
- **端末制約 XD0 / XD1**：私物 PC とスマートフォンを自由に使える人と、個人の認証情報を保存できない共用 PC しか使えない人。
  `contextAndConstraints` を変えます。利用可否を判断するために必要だと思う情報が変わるかを調べます。

ファイル対応と変更フィールドは [set.json](set.json) に記録しています。
各ペア内では、追跡用の `id` と表示用の `name`、上記フィールドだけを変え、他の値は同じにしました。
ペアをまたぐと複数の条件が変わるため、全 8 条件を並べるだけで属性単独の効果を認定しません。
名前もモデル入力であり、利用経験から知識をモデルが補う可能性も残ります。

## 使用範囲

想定する共通の目的は [既存の探索チャーター](../../virtual-beta/public-passkeys-charter.json) にあります。
Persona に対象 URL、候補 ID、正解のページ名、クリック順序は書いていません。
一般的な用語の事前知識と、画面から新しく知り得る GitHub 固有の情報を区別します。

端末制約は Persona の仮定です。
実際のブラウザーの機種、OS、管理者権限や端末ロックを切り替える実装は、この追加に含みません。
読み取り専用の情報探索では、実際の登録操作や規定違反を確認できたとは扱いません。
必要な説明が取得済みの 4 ページになければ、探索範囲による情報不足の可能性も分けて確認します。

JSON は既存 `parsePersona` で読み込みを確認しています。
この定義を用いた実行の有無と実数は、別の実験記録に残します。
画像抽出の出力上限、形式不整合、タイムアウトが改善したことも意味しません。

単体 Persona は既存の入力形式で読み込めます。
一括実行では `--persona-set experiments/persona/extreme-passkeys-v1/set.json` でこの 8 条件を明示的に選択できます。
指定しない場合は既存の baseline / A / B / C のままです。
`--max-decisions 1` は初回判断の後で計測を打ち切り、未達を失敗にしたり目的を変更したりしません。
比較実行では、同じ画面の初回判断を複数回比較する段階と、その後の探索全体を比較する段階を分けます。
途中の応答不正を人間の迷いや離脱として数えず、[ログ一覧](../../../docs/virtual-beta/exploration-observatory.md) に原本を残します。
