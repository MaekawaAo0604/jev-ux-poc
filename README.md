ユーザーの目的・現在見えるUI・操作履歴からJevが次の操作を選ぶ、ローカル専用PoCです。Good/Bad UI × 文字サイズ情報なし/あり × 2 Goalを実行します。

## 実験

`.env.example` を `.env` にコピーし、Vercel AI GatewayのAPIキーを `AI_GATEWAY_API_KEY`、またはTypeSafeのAPIキーを `TYPESAFE_API_KEY` に設定します。両方ある場合はVercelを使用します。APIキーはサーバー側だけで使い、レポートに保存しません。

```powershell
npm run experiment
npm run experiment -- --repeat 3 --goal invoice
npm run experiment -- --max-actions 0 --headed
npm run experiment -- --pom auto --success both
npm run experiment -- --pom manual --success oracle
npm run experiment -- --pom auto --success jev
```

サーバーは自動起動・終了します。各試行で独立したブラウザーコンテキストを作り、試行中は同じページ・セッションを維持します。Jevには全操作履歴を毎回渡します。`--max-actions 0` は回数制限なし（既定20）。同じ画面・同じ操作の3回目でループ終了します。APIは30秒でタイムアウトします。

実行後に表示される `reports/<日時>/index.html` を開いてください。各Stepの入力、候補、確率、操作結果、URL、スクリーンショット、判断時間、全体時間を保存します。結果は逐次保存するため、中断しても完了済みStepは残ります。

## 画像入力の検証

`--vision` を付けると、判断直前に保存したスクリーンショットも Jev 1.14 に渡します。
既定では、現在の操作候補に `[e1]` などの番号を付けた画像から Jev が次の操作を選び、保持済みの DOM 要素を Playwright が操作します。
OCR は起動せず、OCR の文字候補照合や文字メモも作りません。
公開サイトでは、文字のないリンクも既存の安全分類を通過したものに限って番号で提示します。フォーム送信や任意座標の操作を許可する変更ではありません。
番号と操作先の位置は各 Step の `visualTargets` に残します。番号表示は撮影時だけ追加し、成功時も撮影失敗時も片付けます。密集した番号は重ならない位置へ配置し、線で操作先へ対応付けます。
探索判断には現在画像を 1 枚だけ送り、過去画像は再送しません。DOM の観測本文と操作履歴は残りますが、画像だけにあった過去の情報は保持されません。その不足をサイトの UX 問題と断定しないでください。

画面情報を画像だけに限定する実験では、`--vision --image-only` を指定します。
Jev には Goal、現在の番号付き画像、匿名の操作候補、実行した操作の履歴と位置情報だけを渡します。
DOM の本文、タイトル、ラベル、URL は、完了の再確認や別ルート選択を含め、送信直前に除きます。
DOM は操作先の特定、安全確認、ローカルログに残します。終了後の DOM 監査は実行しません。
OCR と過去画像の内容保持は使わないため、複数画面の情報を合わせる Goal を完了できない場合があります。
このモードの試行はサイトの UX 指標の有効件数に含めません。
終了後の保存画像監査は探索とは別に実行し、その結果で探索の終了理由を変更しません。

```powershell
npm run explore -- https://www.ndl.go.jp/ "東京本館を初めて利用したい。事前の利用者登録が必要か、登録に使える本人確認書類を知りたい。" --reviewed --vision --image-only --interval-ms 2000 --max-actions 0
```

`--reviewed` は、実行時点でサイトの利用ルールと探索範囲を確認した後だけ指定してください。
公開サイト探索では、既知の認証用 URL とログインなどの操作リンクを候補から除外し、実行直前、HTTP・画面スクリプトのリダイレクト先、ブラウザーからの認証用リクエストも送信前に検査します。
同じドメインにあるという理由だけで認証を許可しません。料金ページや `/help/login` などの説明ページは引き続き読めます。
画像やスクリプトなどのサブリソースは、自動リダイレクトと自動再試行を止めて 1 回だけ取得し、その応答をブラウザーで再利用します。
サブリソースが HTTP リダイレクトを返した場合は探索範囲外として停止します。無害なリダイレクトでも表示確認ができなくなる制約があり、その試行をサイトの UX 問題には数えません。
この検査は URL の経路・操作用クエリーとリンク表示による保守的な判定です。未知の URL で実装された副作用まで判別する保証ではなく、サイトの利用ルール確認に代わるものでもありません。
`--image-only` は `--vision-ocr` と併用できません。既存の画像と DOM を合わせた経路は変更していません。

画像からの判断記録を次の判断に渡す場合は、`--vision --image-only --image-memory` を指定します。
Goal の原文を句読点などで区切り、各断片について現在画像で確認できたかを Jev の Choice で記録します。
現在画像で見えないだけなら以前の記録を残し、取消・矛盾・不明を示す判断があれば完了を保留します。
入口の有用さも、現在画像の番号と既存の探索対象 ID を対応させて記録します。
判断記録には画像の SHA-256、ステップ、匿名ページ ID を付け、次の判断に渡します。DOM 本文、OCR、自由文の回答、過去画像の再送は使いません。
全更新はログに残し、送信時は各項目の現在の状態、その状態を確定した最新の出典、更新回数へまとめます。現在画像で見えないだけの場合は、以前の確認元を残します。

この記録はモデルの判断であり、正確な回答文や検証済みの事実ではありません。
断片の分割だけでは Goal の網羅性を保証できないため、元の Goal 全体の完了照合も残しています。
未確認・取消・不明の項目が残れば、完了という返答でも終了を認めず、元の返答と保留理由を別々に記録します。
画像由来の確認項目が揃った時点でも、一次判断の `done` を待たずに全 Goal を照合します。不足・不明なら元の操作を維持し、完了を強制しません。
送信時は同一の出典を `imageJudgments.sources` へまとめ、各記録の `source.reference` から参照します。別ルートをグループで比較するときは、その質問に含まれる入口の記録だけを渡し、保存ログは削りません。
未確定の経由移動では、到達できる既知・未探索先が一意の場合だけ、許可済みの一次判断を再判断せずに固定します。
複数の目的地が同じ移動を経由する場合は、候補順や距離だけで目的地を決めず、既存の Jev の経路選択を使います。その選択で停止やエラーになった場合、勝手に先頭候補へ進みません。
現在画像の一意な未試行操作と、確定した目的地への経路継続、探索済み除外は維持します。
終了画面の保存に失敗した場合は `finalCapture` に別記録し、探索の終了理由や Action Trace を撮影エラーで上書きしません。撮影に失敗した試行は UX 指標から除外します。

完了照合だけに必要な出典画像を追加する場合は、さらに `--image-memory-proof` を指定します。
操作判断は現在画像 1 枚のままです。
完了照合では、現在 `observed` の各確認項目を確定した最新画像だけを保存 PNG から読み込み、記録済み SHA-256 と一致したものを現在画像に追加します。
同じ出典は重複送信せず、取消・不明になった項目や入口の見込みだけの画像は選びません。
全履歴画像をメモリに保持せず、OCR や DOM 本文も使いません。
出典が欠落・改変していたら照合を停止し、黙って根拠を省略したり完了にしたりしません。
各要求の `completionProof` に出典、照合状態、画像数を記録します。
この方式でも、画像の意味を Jev が正しく判断することや、Goal の分割が十分なことは保証しません。

```powershell
npm run explore -- https://www.ndl.go.jp/ "東京本館を初めて利用したい。事前の利用者登録が必要か、登録に使える本人確認書類を知りたい。" --reviewed --vision --image-only --image-memory --image-memory-proof --interval-ms 2000 --max-actions 0
```

従来の OCR 文字メモが必要なら、`--vision --vision-ocr` を指定します。この経路は従来どおり番号なしの現在画像を使います。
以下の OCR 処理は、この明示オプションを付けた場合だけ実行します。
OCR 候補の文字照合は Goal や操作履歴を渡さず、操作選択とは別に行います。Jev が承認した文字と出典を後の判断へ残しますが、この承認は独立した正しさの保証ではありません。
既存の Tesseract に加え、利用可能な Windows 日本語 OCR を未確認領域の候補生成に使います。追加エンジンが使えない場合も Tesseract は動作し、その状態は `ocrDiagnostics` に残ります。Windows OCR は認識スコアを返さないため、架空の信頼度は付けません。
追加候補を照合する際は、同じ現在画像の一部を最近傍法で拡大して併送する場合があります。元 PNG は変更せず、切り出し位置と元画像・拡大画像のハッシュを記録します。拡大画像も過去の判断へ持ち越しません。
送信時は同一画像の出典を `visualSources` で共有し、文字メモの `source.reference` から参照します。保存ログは出典を展開したままです。情報の切り捨てはしていませんが、長い探索では API の入力上限に達する制約が残ります。
証跡用PNGと終了後の画像監査は別に残します。OCR言語データは `.cache/ocr` を使い、未取得なら初回にダウンロードします。
実測では、拡大画像を使っても誤った文字列を Jev が承認するケースが残りました。モデル承認済みの画像文字だけで、サイト側の UX 問題と断定しないでください。制御サイトの独立照合で不一致があった試行は、UX 指標から除外します。
現在地点の未実行対象に一意に対応する click／scroll は、画面を見た Jev の選択をそのまま探索記録へ確定します。同じ操作をもう一度選ばせて停止へ上書きしません。Back、経由移動、確定済み経路の継続は既存の別ルート処理を使います。
Vercel の `AI_GATEWAY_API_KEY` が必要です。
実行方法と比較結果は [画像入力の検証](docs/vision-validation.md) を参照してください。

```powershell
npm run experiment -- --vision --variant good --goal notifications --font on --pom auto --success both --max-actions 0
```

全テストの PC 負荷を抑える場合は、ファイル単位の並列実行を止めます。実サイト探索と同時には実行しないでください。

```powershell
npx tsx --test --test-concurrency=1 tests/*.test.ts
```

## APIキーなしの動作確認

`--pom manual`（既定）は手書きPOM、`--pom auto` は現在画面からリンク・ボタンを自動抽出する実行時POMです。今回のデモ用で、フォーム入力・iframe・任意サイトの完全対応は含みません。DOM内部属性や遷移先はJevに送りません。抽出順序が異なるので、手書き版との比較には候補順序の影響も含みます。

`--success both`（CLI既定）は処理成功後も探索を続け、Jevの `done` と処理結果を照合します。`oracle` は従来どおり処理成功で即終了、`jev` はJevの `done` を主判定（PERCEIVED_SUCCESS）として終了し、実処理結果も監査用に記録します。成功したのに認識できない／未達なのに完了と判断するケースを別々に記録します。APIエラーで中断した場合はUXの失敗と断定しません。処理成功の内部フラグはJevへ送信しません。

レポートの候補確率は「表示名 (e2): 70%」形式です。過去のログも `npx tsx runner/render.ts reports/<実行日時>` で再描画できます（API再実行なし）。

### 操作経路図

レポートで試行を開くと、スクリーンショット → 選んだ操作 → 次の画面を順に表示します。
処理成功・途中停止・ループ・判断APIエラーなどは日本語で区別し、Jevの完了判断だけでは「処理成功」にしません。
PCでは横スクロール、狭い画面では縦に表示します。画像を押すと元画像を開けます。

- 同じURLと観察情報に戻った画面には「再訪」を表示。画面名だけの一致では判定しません。
- ループでブロックされた操作や `done` / `stuck` は実行済みの矢印にしません。
- 判断前の画面と、最後の操作後の画面を区別します。画像が欠けたログは代替表示します。
- 候補の確率・判断入力・実行ログは折りたたみ内で確認できます。
- 共有する場合は `index.html` だけでなく、画像・JSONを含む実行フォルダー一式が必要です。URLや画面内容に個人情報がないか確認してください。

保存済みの主実験を再描画する例（追加課金なし）：

```powershell
npx tsx runner/render.ts reports/2026-09-18T19-37-43.902Z
```

```powershell
npm run demo
npm test
npm run build
```

`--fake` は意図的に固定ルールで操作する配線確認専用です。Jevの成功率・UX評価の証拠には使えません。Chromiumがない場合、インストール済みChromeは `$env:PLAYWRIGHT_CHANNEL='chrome'` で使用できます。

## 成功経路から回帰テストを生成する

既存の探索に **Action Trace**（実行した操作と Locator 用の情報）を追加しました。
画面の観測、Jev の操作選択、Playwright の操作実行は従来の処理を使います。
Locator 用の内部属性は別ログに保存し、Jev の入力には追加しません。

```powershell
npm run experiment -- --variant good --goal notifications --font on --pom auto --success both --repeat 1 --max-actions 8 --generate-test
npm run test:raw -- --repeat-each=3
npm run test:regression -- --repeat-each=3
```

探索ごとに `reports/<日時>/<試行>/action-trace.json` を保存します。
`--generate-test` を付けると、Jev の完了判断と既存の成功条件が両方成立した経路から、`generated/raw/<日時>-<UUID>.spec.ts` と元 Trace のコピーを生成します。
既存の raw ファイルは上書きしません。
raw が複数ある場合は `npm run test:raw -- <対象ファイル名> --repeat-each=3` で対象を指定できます。

保存済み Trace からの生成には API キーも Jev も不要です。

```powershell
npm run generate:test -- reports/<日時>/<試行>/action-trace.json
```

最初の対応範囲は、ローカルデモの `notifications` Goal です。
公開サイトの未検証の完了宣言、請求書ダウンロード、失敗した探索、不完全な Trace、対象が一意に決まらない Locator からは生成しません。
`fill`、`select`、`press` は Trace と生成器の形式として扱えますが、現在の Jev 探索には入力操作を追加していません。
`--fake` で作った raw には FAKE と明記し、Jev の性能評価には使いません。

Codex が手直しした通常テストは `tests/regression/notifications.spec.ts` です。
既存の `GoodPage` と `tests/goals.ts` を再利用し、新設の fixture でブラウザーを準備します。
Jev の呼び出し、固定時間の待機、操作順の変更はありません。
raw と通常テストはどちらもローカル以外への通信を止め、操作後の URL と成功条件を確認します。
回帰テスト用サーバーはポート 5188 を使用し、既存の 5173 のプレビューには触れません。
Codex による POM 化は今回の作業で実施したもので、CLI から Codex を自動起動する仕組みではありません。

## 公開サイトを探索する

候補と目的の例は [公開サイトの探索候補](docs/public-site-candidates.md) にあります。
サイトごとの規約、robots.txt、探索範囲を確認した後に、1 件ずつ実行します。
`--reviewed` は実行者による確認の申告であり、プログラムによる規約の審査ではありません。

```powershell
npm run explore -- "https://example.com/" "料金と利用条件を知りたい" --reviewed --max-actions 20 --interval-ms 2000
npm run explore -- --help
```

開始 URL は対象サイトに置き換えてください。
結果は `reports/<日時>-public/index.html` に保存します。
公開サイトの操作数は、既定では制限しません（`--max-actions 0`）。
正の整数を指定した場合だけ、その回数を上限とします。
上限ちょうどの操作後にも画面を観察して Jev が判断し、追加操作が必要なら実行せずに終了します。
待機時間は 1,000 ミリ秒以上で指定し、既定は 2,000 ミリ秒です。
操作数が無制限でも、同じ画面での同じ操作の繰り返しや、安全境界を越える操作は防ぎます。
公開探索では、実行した操作と再観測した結果を実行側の探索メモリに記録します。
画面内で振り直される要素 ID や文字サイズではなく、観測本文・表示位置・操作対象で状態と操作を区別します。
URL を訪れただけで、そのページを読み終えたとは扱いません。
試した操作は候補から除外しますが、既に観測した未試行のリンクやスクロールへ進める経路は再通過できます。
直接リンクの実行結果は「送信元ページ＋リンク先」で共有します。同じヘッダーリンクが別のスクロール位置に現れても未試行には戻しません。スクロール・開閉・戻るの履歴は画面状態ごとに保持します。
経路の判定には直近の実行結果を使い、以前は進めたリンクでも、最後に確認した結果が行き止まりならその古い経路を再利用しません。
再通過を選んだ区間では、未試行操作に進むまで同じ道を戻る候補を外し、未試行操作を実行したら通常の候補選択へ戻します。
その画面に未試行のリンクが残っていても、別の未試行操作へ進める経路は残します。たとえば、未試行のヘッダーリンクを押さなければ下へスクロールできない、という制約にはしません。
ブラウザーの「戻る」は現在の履歴に依存するため、過去の戻り先を再通過経路の根拠にはしません。通常時の戻る操作は残し、再通過で以前と異なる状態に着いた場合も経路を解除して戻れるようにします。
リンク先や開閉対象の識別情報は実行側だけで使い、Jev の画面情報には追加しません。
除外理由と再通過候補はレポートの `explorationMemory` に残します。これは探索方針の変更であり、人間の迷いをそのまま測る条件ではありません。
過去の画面で読んだ本文も `history[].observedText` に残し、画面をまたぐ条件を Jev が参照できるようにしています。
観測済みの本文と位置・局所文脈は、履歴の件数や文字数で切り捨てずに保持します。
以前の記録に `observationOmitted` があれば、その欠落情報も保持します。
元の画面の読み取り警告も `observedWarnings` に残し、部分的な文字列を完全な情報と取り違えないよう判断時に伝えます。
ページの本文が準備できてから観察します。
読み取り中の文書切り替えで観察が無効になった場合は、観察だけを最大 2 回やり直し、クリックなどの操作は再実行しません。
ラベルの文字を観察できない画像だけの操作は、原則として候補から除外し、`UNLABELED_CONTROLS_EXCLUDED` を記録します。
例外として、ヘッダー内に小さな画像・図形の開閉操作と別のナビゲーションパネルを一つずつ特定できる場合は、画面上の位置を説明して候補にします。
この場合も `text` は空のまま、`description` に「文字は未取得」と明記し、`NON_TEXT_CONTROL_DESCRIPTION` を記録します。
画像の代替テキストや未表示のパネル本文を、読めた文字として渡すことはありません。
任意の画像リンクや判別できない独自ボタンは引き続き対応範囲外です。
待機時間は初回の移動後と各操作の後、次の観測を始める前に適用します。
操作間隔を保ちつつ、操作直後のアニメーション途中の表示を拾いにくくします。
すべての表示変化の終了を保証するものではなく、画像など個々のリクエストの間隔も制御しません。

探索ごとに新しいブラウザー環境を使い、同一オリジンのリンク遷移、戻る、スクロール、一部の表示開閉に限定します。
リンクのクリック処理は実行せず、リンク先へ直接移動するため、人間の操作を完全には再現しません。
表示開閉は `details/summary`、対応パネルを特定できる ARIA ボタン、Schema.org の Question/acceptedAnswer の組を対象にします。
ヘッダーの画像・図形による開閉も、操作候補や対応パネルが曖昧な場合、入力や編集を伴う場合は許可しません。
ナビゲーションパネル内の GET 検索フォームは表示だけ許可しますが、検索の入力・送信は行いません。
開閉は実際にクリックして表示の変化を確認し、その後の通信を次の明示的なページ移動まで遮断します。
WebSocket、ポップアップ、ダウンロードも制限します。
任意のボタンやフォーム内のボタンは許可せず、実行できない操作は選択候補から外します。
フォーム入力、送信、PDF の読解、ログイン、購入は未対応です。
明示的なリンク遷移では、HTTP リダイレクトの各転送先を確認し、同一オリジン内で最大 3 回まで進みます。
外部オリジン、認証情報付き URL、ファイル、循環する転送は取得前に拒否します。
確認済みの最終応答を再利用し、ブラウザーの自動転送で検査を迂回しないようにします。
ページ内スクリプトなどによる予期しない転送は停止します。
GET と HEAD 以外の通信を遮断しますが、GET に副作用があるサイトやページ内スクリプトの動作まで無害と保証するものではありません。

Jev の完了判断は、目的を実際に達成したかを検証した結果ではありません。
未対応コンテンツ、探索範囲外、アクセス制限、API エラーを UX の問題と分けて記録します。
画面内の DOM テキストを文字領域ごとに取得します。
見出しや段落だけでなく、`div`、`span`、表、箇条書きも対象です。
各領域には一時 ID、文字列、ビューポート基準の座標を記録します。
文字サイズを有効にした場合は、領域内の最大フォントサイズも記録します。
非表示、透明、画面外、クリップされた文字を除外し、文字の一部しか取れない場合は警告を残します。
クリックを透過する描画要素との重なりは、描画順を断定せず保守的に除外します。
絶対配置の疑似要素は、単純な配置で文字に重ならないと確認できる場合だけ装飾として扱い、リンク名を残します。
通常書式の単一生成文字は描画幅を測り、本文と横方向に重ならない場合だけ許可します。
影、縁取り画像、反射、移動経路、複雑な変形など、描画範囲を確認できないものは除外します。
このため、見えている文字を省略する場合もあります。
画像内の文字、疑似要素、Shadow DOM、複雑なマスクや重なりを含む描画全般には対応していません。
OCR は探索に接続していません。
営業資料や記事への転用前には、人が経路と内容を確認し、画像や名称の掲載可否も確認してください。

### 項目別の到達判定（実験用）

`--goal-check` を繰り返し指定すると、完了判定を操作選択から分けます。
各項目は目的文からの抜き出しに限定し、答えや操作経路は設定しません。
目的を作る段階で人または GPT が項目に分け、その後はスクリプトと Jev で探索できます。

```powershell
npm run explore -- "https://example.com/" "利用料金と営業時間を知りたい。申し込みはしない。" --reviewed --goal-check "利用料金" --goal-check "営業時間"
```

Jev は項目が目的を網羅しているかと、各項目の情報が観察済みかを別々に判断します。
項目に漏れがある、または網羅性が不明な場合は `GOAL_CONFIG_ERROR` として操作前に停止します。
取得済みと一次判定した項目から、本文の根拠を個別に照合します。
未取得の項目が残っていても、取得済みの根拠と進捗を保持します。
観察した本文をページ・見出し・領域ごとのブロックにまとめ、関連性を先に判定します。「不明」は残し、「無関係」も元の引用とともに記録します。古いログでページ識別情報がない場合は、異なる観察をまとめません。
残したブロックの本文を項目ごとに「直接の根拠」「関連する説明」「無関係」「不明」に分類します。その後、対象への適用と情報の十分性を独立した質問で判断し、生の回答を両方記録します。
引用を選ぶ段階では、要求の一部に答える事実も残し、対象の一致と情報がそろったかどうかは後段で確認します。
複数人の料金などでは、1 つの引用が全員に適用されることは要求しません。
その情報項目で求める対象への適用を確認し、全員分がそろったかは十分性の判定で確認します。
判定基準はユーザーの要求項目であり、可否への否定回答も「可否が分かった」に含めます。
方法だけを尋ねたときに、未指定の電話番号・所在地・具体的な時刻を必須条件として追加しません。
各項目に直接の根拠があり、対象が一致し、必要な情報がそろい、矛盾・例外の確認も済んだ場合だけ `done` で終了します。
対象が不明・不一致、または直接の根拠がゼロなら、十分性が `present` でも完了を止めます。
矛盾の確認では、同じページで観測した本文と凡例をまとめて渡し、複数回の照合に分けます。
観察部分の入力は 16,000 バイトを目安に分けますが、単独で超えるページは分断せずに渡します。
全バッチが確認済みになるまで完了にはせず、矛盾・不明・通信失敗を成功に読み替えません。
操作選択には不足項目と、実際に観察した範囲・訪問・実行済み操作の進捗を渡します。そこで別途 `done` を選ぶことはできませんが、ほかの候補は保持します。
このモードの操作入力では、同一の観測本文を `observations` にまとめ、順序付きの操作履歴から `observationId` で参照します。
本文・ページ・警告・省略状態が異なる観測はまとめず、元の履歴と引用元の記録も保持します。
入力は実際の観察本文と履歴に限定し、正解や未表示の情報は渡しません。
設定、各項目の一次判定、根拠付き判定、網羅性、API 試行履歴を JSON に残します。
引用文は Jev に生成させず、選ばれた ID に対応する観察本文をそのまま記録します。
レポートから引用元の画面を確認でき、関連する説明や読み取り制約も区別して表示します。
到達判定の確率と、操作選択の確率は別物として記録します。
初回はブロックのスクリーニングと一次判定を可能な範囲で同じ呼び出しにまとめます。追加観察時は成功済みの完全一致する入力バッチを再利用し、新しい入力だけを評価します。一次判定が `present` の各項目について、本文の分類と対象・十分性の照合を行います。
分類は 1 回あたり最大 96 質問に分割し、古い観察をこの上限のために捨てることはしません。
成功したリクエストは探索フォルダーの `evidence-session.json` に保存します。キーは目的、項目、日付、設定モデル、プロンプト版、実際の入力と質問に対応し、引用元 ID はキャッシュに入れず現在の観察へ対応付けます。新しい例外が加われば最終照合は再評価します。
`createEvidenceSession({snapshot, checkpoint})` と `assessGoal(state, checks, session)` で、保存した同じ状態の判定を途中から再開できます。別の目的・項目・日付・モデル、壊れたスナップショットは未キャッシュとして扱います。CLI は実行ごとに新しいセッションを作り、ブラウザーの途中再開は行いません。
`result.evidenceSession.accounting` に探索全体の論理呼出し数、通信試行数、失敗数、質問数、再利用数と段階別集計を記録します。`requests` はリクエストごとの安全なメタデータです。終了後の確認は `completionAudit.request` に別記録し、合計通信試行数は両者を加算します。観察量や文脈の変化によって費用は増え、削減率は実測が必要です。

根拠照合を追加する前の検証では、保存済み記録から年齢条件を消しても、残った手続き説明だけで「対象条件」を取得済みと判断しました。
根拠の分類と回答可能性の判断も Jev が行うため、引用を付けただけで誤完了がなくなるとは限りません。
大まかな項目の完全性を保証するものではなく、Jev の `done` は客観的成功に格上げしません。
既定は従来方式のままです。比較時は `settings.decisionMode` と `goalChecks` を確認してください。

### 終了後の根拠確認

実モデルの探索が `done` で終了した場合、観察済みの表示と操作結果を Jev で再評価します。
証拠が少ない場合の追加 API 呼び出しは 1 回です。
多い場合は完了判断を 1 回行い、証拠の質問を 8 件ずつに分けて送ります。証拠数に応じて呼び出しと利用料が増えます。
`--fake`、`stuck`、エラーによる終了では呼び出しません。

レポートには、再評価の結果と、根拠として選ばれた文字列、元の画面へのリンクを表示します。
これは探索時の思考過程を取得したものではなく、客観的な成功確認でもありません。
再評価が失敗しても、探索時の `done`、終了理由、スクリプトによる成功判定は変更しません。
失敗箇所を入力の組み立て、API 通信、返答形式の検証に分けて記録します。
通信エラーは定型コードと HTTP ステータスだけを保存し、例外に含まれる認証情報やリクエスト本文は保存しません。
タイムアウト、HTTP 408・429・5xx は、2 秒、4 秒の待機を挟んで最大 2 回再試行します。
各試行のタイムアウトは 30 秒です。
API の再試行中にブラウザー操作は繰り返しません。
認証エラーや不正な返答は再試行せず、返答形式の失敗は通信エラーと区別します。
判断結果と根拠確認の `request` には、API 試行回数と定型化した失敗履歴を保存します。
古いログの再描画では根拠を後付けせず、「記録なし」と表示します。

DOM 抽出は可視範囲を含むテキストノードを 60,000 文字まで処理し、到達時は観察情報に警告を残します。
完了後の再評価には、観測した証拠と操作結果を件数・文字数で切り捨てずに入力します。
モデル入力には ID・取得元・本文を渡し、画面上の位置とステップ番号はレポート用に保存します。
証拠ごとの質問は 8 件ずつに分けますが、各入力には証拠全文を含めます。
省略、部分的な読み取り、根拠未選択は警告として残します。
DOM 読み取り量や API 自体の容量・タイムアウトには制約が残ります。
これらの制約で判定できなかった場合は、成功とは扱いません。

## 保存したスクショの OCR を確認する

**OCR 確認画面**では、保存済み PNG から読み取った文字と、その位置を枠で表示します。
画像はローカルで処理し、Jev の呼び出しや対象サイトへの再アクセスは行いません。
初回のみ Tesseract.js の英語と日本語のモデルを取得し、`.cache/ocr/` に保存します。

```powershell
npm run ocr -- reports/2026-09-19T14-30-22.910Z-public/exploration/step-2.png --step reports/2026-09-19T14-30-22.910Z-public/exploration/step-2.json
```

`--step` は省略できます。
指定すると、当時 Jev に渡した DOM 由来の文字も比較用に表示します。
古いログに座標がないため、DOM 側の枠や OCR との自動差分は表示しません。

出力は新しい `reports/ocr-<日時>-<識別子>/` に保存し、元画像と過去の実行結果は上書きしません。
`index.html` を開き、一覧から文字を選ぶと対応する枠が強調されます。
検索、枠の表示切替、元画像の表示、読み取り結果 JSON の保存ができます。
JSON には元画像の SHA-256、行ごとの文字と座標、認識スコア、初期化時間と OCR 処理時間を記録します。

認識スコアは正答率ではありません。
60 未満の行には確認用の破線を付けますが、それ以上でも誤読することがあります。
金額、通貨記号、課金単位、色付きの文字は元画像と照合してください。
誤読や文字間の空白は自動補正していません。
現段階では Tesseract.js のみを使用し、PaddleOCR との比較や DOM と OCR の統合は未実装です。

入力はローカルの PNG に限定し、32 MiB、2,400 万画素、各辺 16,000 px を上限とします。
OCR の初期化と認識は 120 秒で打ち切ります。
画像そのものは拡大加工せず、元画像の座標を使います。

通常の `npm test` はモデルの取得を必要としません。
モデルを取得済みの環境では、次のコマンドで実際の OCR もテストできます。

```powershell
$env:RUN_OCR_INTEGRATION='1'
npm test
Remove-Item Env:RUN_OCR_INTEGRATION
```

## ローカル実験の構成

- `app/`: 同一機能のGood/Bad画面。Badは抽象ラベル、階層、小さい文字、目立つ無関係な導線を含みます。
- `pages/`: 手書きPOM。操作対象を明示定義し、ビューポート内・非遮蔽・有効な要素のみ一時IDに対応づけます。URL、selector、POM名、遷移マップはJevへ渡しません。
- `jev/`: 公式REST APIのChoice呼び出しとレスポンス検証。API失敗時にFakeへ切り替えません。
- `runner/`: 独立した成功判定、終了条件、レポート。`done`だけでは成功しません。請求書は先月のファイル名とPDFヘッダー、通知は停止メッセージを検証します。
- `tests/`: Goal定義と境界検証。

文字サイズ比較では同じ画面から `fontSizePx` だけを除外します。
文字領域の位置は両条件で渡しますが、太さは未実装です。
スクリーンショットは監査用で、Jev へ送りません。
小さな文字を数値で伝えても、人間の視覚や注意を再現する保証はありません。
繰り返し試行で毎回違う結果になる保証もありません。

2つのページには階層の深さの違いもあるため、操作数の増加だけでは「迷い」と断定できません。経路、戻る、停止、候補分布を併せて確認してください。支払い方法変更、SaaS、汎用POM、総合UXスコアは含みません。

公式仕様: https://docs.typesafe.ai/introduction/quickstart / https://docs.typesafe.ai/primitives/choice
`POST https://api.typesafe.ai/v1/systemone` / `questions.nextAction.criteria` / `answers.nextAction.probabilities` を使用。
