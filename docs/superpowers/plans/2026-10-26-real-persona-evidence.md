# 実ページ上のペルソナ判断差の検証計画

Goal: 基盤の修正ではなく、元のA/B/Cの違いが実ページの次の操作に反映されるか、条件内のばらつきを上回る差と独立した再測定で確認する。ユーザーは実行を繰り返し指示済み。既存のJevの入力と判断は変更しない。

- 実ページ: GitHub Docs日本語の2FA一覧とパスキー一覧。SVGOMG初期画面は明確な入口の対照。画面・目的・候補・履歴なし・モデルを条件間で同一にする。説明／設定の分類はURLを画面認識の裏側で記録し、Jevには正解手順や仮説を渡さない。
- 事前固定: 各主要画面でbaseline/A/B/Cを20回、その後に別の10回で確認。知識だけ交換したA_kB/B_kAを各主要画面10回。SVGOMG対照は各5回。計300判断。条件順はブロック内で固定シードによりランダム化。途中結果で画面・目的・ペルソナ・標本数を変更しない。
- 主指標: 実際に選んだ操作の意味を正規化したTV距離（条件間平均−条件内平均）。反復ブロック内の条件ラベル置換9999回、2画面のHolm補正。主試行と確認試行の両方で補正p<.05、効果>=.10が必要。知識交換と理由確率は副次的。人間・内部思考・探索全体への一般化はしない。
- 実操作: モデル入力は実サイトで取得した同一の画像とDOM。選択されたリンクの到達先を同じサイト上で確認し画像とtraceを保存する。さらに各条件の代表となる初手から自律探索の継続を検証する。到達先確認や継続を統計標本と混ぜない。
- 出力: manifest（事前計画・source/PNG hash）、各入力・質問・選択・自己申告理由・APIメタデータ、実操作の画像/trace、比較JSON/HTML。欠測やモデル・入力不一致があれば有意性を主張しない。

## 実装順

1. 実画面を取得し候補化・画像を確認する。まだモデル判断を取らない。
2. 既存のanalyzeProbesを再利用し、実データの正規化・確認試行の合格条件・欠測時無効化をテスト先行で実装する。
3. 計画とsourceを固定し300判断を実行。条件間入力hash照合、同じペルソナのばらつきと比較。
4. 実リンクの到達先・継続探索を記録。基盤に問題が出た場合は原因を保存し、標本の成功選別はしない。
5. 比較レポートを生成しレビュー・参照先・表示を検証する。
