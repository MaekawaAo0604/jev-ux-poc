# Qiita 記事の構成案

このファイルは執筆前の編集メモです。
本文は、実験の経緯と結果を主軸にし、仕組みを理解して試せる範囲のコードを添える構成を想定しています。
文体は「です・ます」、読者は Web 開発や E2E テストの経験がある開発者、本文はコードを除いて 5,000〜7,000 字を目安にします。

## 記事の主張

正解手順を渡さず、画面から抽出した情報と操作履歴だけで Jev に次の操作を選ばせたところ、自作した 2 種類の UI で到達結果に差が出ました。
実サイトでも入試情報のページまで進めましたが、募集要項の PDF を扱えず、探索が止まりました。

「UX を自動評価できた」「人間の迷いを再現した」「E2E テストを置き換えられる」とは書きません。
今回は、導線の変更による行動差を記録できるかを試した事例です。
実運用での回帰検知能力や、人間の利用結果との一致は未検証です。

## 仮タイトル

第一候補：正解手順を教えずに Web サイトを操作させる。Jev と Playwright で導線を検証してみた

別案：Jev に「請求書を保存したい」とだけ伝えて、Web ページを探索させてみた

タイトルには「人間のように」「完全自動 UX 評価」「爆速」「成功率 100%」を入れません。

## 見出し案

### 1. 正しい操作手順を知らなくても、目的にたどり着けるか

通常の手順固定型 E2E テストは、指定した操作を行えるかを確認します。
その導線を知らない利用者が目的の機能を見つけられるかは、別の確認が必要です。
「先月の請求書を PDF で保存したい」を例に、今回の問いを説明します。
E2E テスト一般に UX の確認能力がない、とまで広げません。

目安：400〜600 字。

### 2. Jev に選択させ、Playwright で操作する

Jev は型付きの判断を返すモデルで、今回は Choice を使います。
Goal、現在の可視情報、操作履歴を入力し、クリック・戻る・スクロール・done・stuck から次の操作を選ばせます。
`e2` は、その観察時点の要素と実操作を対応付ける一時 ID です。

フロー図を 1 枚、実際の入力と出力の短い例を各 1 個載せます。
「Jev がブラウザーを直接操作する」「スクリーンショットを理解する」という誤解を防ぎます。
スクリーンショットは記録用であり、Jev への入力はテキストと数値です。

目安：800〜1,000 字。

### 3. 正解ルートを渡さないための実装

ブラウザーは 1 試行中、同じセッションを保ちます。
Jev の各リクエストにはそれまでの操作履歴を渡し、別の試行では新しいブラウザーコンテキストを作ります。
selector、内部 ID、遷移先、成功判定用の内部フラグは Jev に渡しません。

手書き POM と自動抽出 POM を説明します。
自動版は毎画面のリンクとボタンを列挙し、実行時に対応表を作ります。
コードファイルの自動生成ではなく、実行時の要素抽出です。
入力フォーム、画像だけの意味、PDF、iframe を含めた汎用サイト対応は未完成です。

目安：600〜800 字。

### 4. 同じ機能で導線を変えて比較する

Good と Bad の画面を並べます。
Bad では抽象ラベル、階層、小さい文字、目立つ無関係な案内を同時に変えています。
複数要因をまとめて変えた実験であり、ラベルだけの効果を測った実験ではありません。

主実験は 2 UI × 2 Goal × 文字サイズ情報の有無 × 3 回の 24 試行です。
これは手書き POM と処理結果による成功判定で行った主実験です。
あとで追加した自動 POM と Jev の完了認識を、この 24 試行に含めません。

Good は 12 試行とも 2 操作で成功。
Bad は請求書の 6 試行で STUCK、通知停止の 5 試行で LOOP、残る 1 試行で API タイムアウト。
API エラーを UX による失敗と数えません。
経路例を示し、モデルが実際に選んだ操作を説明します。

目安：900〜1,100 字。

### 5. 文字サイズを渡しても、今回の経路は変わらなかった

同じページについて、`fontSizePx` の有無を変えました。
完走できた条件の比較では、操作経路の違いを確認できませんでした。
これは「文字サイズは UX に影響しない」という結果ではありません。
Jev に文字サイズを数値で伝える方法が、人間の注意を再現するとは限らないためです。

選択確率と選択された操作も区別します。
「確率分布まで完全に同じ」と書くには、別途ログの照合が必要です。

目安：300〜500 字。

### 6. 操作に成功したことと、完了したと分かることを分ける

処理成功と Jev の `done` を別々に記録する設計を説明します。
「成功したが完了と思えない」「未達だが完了と思う」を区別できます。
これらは仕組みが区別できる事象であり、実 Jev で両方の問題を観測したという意味ではありません。

追加の実 Jev 検証では、Good の 2 Goal を手書き／自動 POM で 1 回ずつ実行し、4 試行とも処理成功と完了認識が一致しました。
この検証は `fontSizePx` なしです。
誤完了などの境界条件はプログラムのテストで確認しています。
モデルの判断力による誤りと、UI の伝わりにくさは今後分けて検証します。

目安：500〜700 字。

### 7. 福井高専のサイトで入学情報を探す

Goal は「福井高専の入学情報が知りたい」です。
自動 POM でトップページから「入試情報」「中学生の入試」へ 2 操作で進みました。
次に募集要項を 2 回クリックし、3 回目を実行する前にループとして停止しました。
試行全体の実操作は 4 回、最終結果は LOOP です。

募集要項のリンク先が PDF であることは確認済みです。
実行器は PDF 内容を観察対象にしていません。
サイトの UX が悪いとは評価せず、ツール側の対応範囲の限界として記載します。
「入学情報を理解できた」「実サイトで目的達成」とは書きません。
中学生向けを選んだのは Jev であり、編入や専攻科まで含む目的だったかは不明です。

目安：500〜700 字。

### 8. 試すための手順と、今回残った課題

Node.js、依存関係、Playwright、環境変数、実行コマンド、レポートの見方を短く載せます。
詳細なインストール手順や全ソースは README に分けます。
費用を載せる場合は実行範囲を限定し、モデル単価と実測費用を混同しません。

課題は、人間の行動との比較、PDF 対応、候補の順序、可視情報の抽出精度、達成判断の誤りです。
「UX 総合点」の導入は提案しません。

目安：600〜800 字。

## 本文で説明する深さ

- Jev：Choice の入力と出力が分かる程度。学習手法や広告上の速度倍率は扱わない。
- Playwright：要素取得、クリック、状態取得が分かる程度。環境構築を一から教える記事にはしない。
- POM：手書きの対応表と自動抽出の違いを説明する。全クラスの解説はしない。
- コード：入力型、Choice 呼び出し、探索ループの 3 箇所を中心に、合計 80〜120 行程度。省略箇所を明示する。
- 実験：母数、条件、打ち切り、失敗理由を省略しない。別の実験の数値を混ぜない。
- 日本語：専門用語は初出で短く説明する。導線、到達、処理成功、完了認識を使い分ける。

## 掲載する素材

1. Good / Bad の初期画面。自作デモの同じサイズの画面を使う。
2. 画面取得 → Jev → 操作 → 再取得のフロー図。入力に含めない情報を注記する。
3. Bad の失敗経路と、表示名付きの候補確率。確率は人間のクリック率ではないと説明する。
4. 主実験の集計。24 試行と、うち 1 件の API エラーを分けて示す。
5. 実サイトの経路。まず文字と URL で示し、スクリーンショット転載の範囲は公開時に判断する。

## 掲載しないもの

API キー、`.env`、アカウント情報、請求画面、ローカルのユーザー名を含むパス、会話ログ全体は載せません。
入金額や無料枠での試行錯誤は、必要なら短い補足に留めます。
GPT が最初の Goal や分類を作る案は未実装なので、実装済みの機能として説明しません。

## 本文の執筆前に決めること

検証記録を主軸にする構成を仮置きしています。
実装チュートリアルを主軸にする場合は、再現環境とコード公開の準備を先に増やします。
リポジトリ公開の可否、著者の一人称、サイト画像の掲載範囲は未決定です。
これらが未決定でも本文の下書きは作れます。

## 公開前の確認

24 試行時点のコードをコミットとして保存していないため、現在のコードで過去の結果を完全再現できるとは書けません。
最終版を再現可能な記事にするなら、バージョンを固定し、公開対象コードで主実験を再実行してから結果を確定します。
モデルも `typesafe-ai/jev` という識別子で記録しており、提供元の内部バージョンは固定していません。
日時、コードの変更、候補順序による違いが出得ることを明記します。

## 日本語の推敲

`japanese-tech-writing` を使用します。
主張と根拠を照合してから、用語、段落、一文の長さを整えます。
冗長な表現を減らしても、実験の条件や不確実性は削りません。
ユーザー自身の感想や動機は、発言にない内容を創作しません。
