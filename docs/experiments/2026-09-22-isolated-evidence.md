# 引用を分離した到達判定の検証

2026-09-22。判定処理を改め、最終候補の保存ログ検証は 16 件すべて期待結果と一致した。
この一致は、他のサイトでの成功率や人間の UX を保証しない。

## 変更した処理

1. Jev が目的文だけから、資格、場所、時間、費用、手順などの情報の種類を分類する。
2. 本文の判定には 1 件の引用だけを渡す。別の引用や周囲の段落を質問文にも混ぜない。
3. 引用ごとに、同じ局所的な文脈を使って対象への適用を確認する。別の制度の文脈は渡さない。
4. 十分性は要求項目ごとに分離し、その項目に採用した引用だけで判断する。制度全体のルールと、特定店舗の具体的な時刻を区別する。
5. 全観察からの矛盾検出は別工程とし、完了を止める側にだけ使う。対象の適用を後段で文脈なしに再判定しない。
6. 次の操作を選ぶリクエストには、領域ごとに重複する本文・座標・文脈を渡さない。元の観察記録と根拠判定には残し、操作選択でも本文・履歴・警告・候補は保持する。

本文判定で直接の根拠を選んでも、出力確率が 0.75 未満なら保留する。
この閾値は保守的な運用条件であり、正答率 75% を意味しない。
採用した引用、除外した引用、元の判断確率を保存する。

キャッシュの版を更新し、旧判定の結果を再利用しない。
同一の本文は再利用し、ページや見出しが変わった場合の適用確認は別に行う。
モデルの別名が提供者側で別の版を指すようになった場合は、ローカルの版管理だけでは検出できない。

## 確認結果

- 保存ログと反例の実 Jev 検証は 16/16 件一致。誤完了 0 件、最終的な通信中断 0 件。
- 正常な高校生制度のログは約 23.5 秒、57 呼出し、再試行込み 58 回。
- 627 断片ある保存ログは約 48.1 秒、113 呼出し、再試行込み 115 回。本文判定は重複を除く 100 件。
- 正常例の保存済みセッションを復元して同じ入力を再判定すると、追加通信は 0 回で引用も一致した。
- 最終コードでの新規実サイト探索は 3 回とも未達。高校生制度は 2 回とも 24 操作で上限、見学方法は 23 操作後にループで停止した。参照条件に対応する本文は高校生 0/5、見学 0/2 項目で、誤って完了とは判定しなかった。
- 最終 3 回の本探索は 149 呼出し、再試行込み 157 回。途中の通信失敗 8 回は回復し、通信による最終中断は 0 回だった。少数回の結果であり、障害がなくなったとは言えない。

最終検証でも途中の通信失敗はあり、既存の回数制限付き再試行で回復した。
開発途中には 503、返答形式の不正、誤完了、正常例の未完了も発生しており、そのログを削除していない。
API 障害が解消したという結論ではない。

## 通信と操作の保護

ページ取得の失敗は DNS、TLS、接続拒否、タイムアウトなどの分類を残す。
API の失敗は段階、HTTP 状態、許可したエラー種別、質問数、入力バイト数、所要時間を記録する。
生の SDK エラーや認証ヘッダーは保存しない。
ページ本文、スクリーンショット、ブラウザー由来のエラー記録はローカルの観察資料であり、共有前の確認が必要。

一括検証の前に対象サイトと Jev の小さな疎通確認を行い、失敗した場合は本検証を未実行として止める。
疎通確認は最小リクエストの確認であり、その後の全リクエストの成功を保証しない。
明示的なページ移動の読み込み中に限り、同一サイト内のクライアント転送を最大 3 回まで許可する。
移動先は事前取得して検査し、観察に移る前にこの許可を閉じる。
クライアント転送の先でさらに HTTP 転送が発生する混合経路は、現時点では安全側に停止する。
フォーム送信は追加の CSP によって禁止する。GET フォームも対象とし、サイト既存の CSP は緩和しない。
承認した「戻る」は事前に応答を用意し、未使用の応答も破棄する。
戻り先が記録した URL と異なる場合も停止する。
安全制限に触れた時点で転送許可を閉じ、取得済みの応答を破棄する。
通信中の応答が遅れて返っても、閉じた許可や取得済み応答を復活させない。
API の返答待ちや操作前の待機中にも制限を確認し、その間の違反を完了判断で上書きしない。

## 残った問題

今回は「見つけた情報を正しく扱う判定」と「目的の情報まで進む探索」を分けて検証した。
保存ログの判定は期待結果に一致したが、実サイトでは一般案内から目的外の記事へ進む、同じ店舗検索を繰り返す、といった経路が残った。

観察側にも制限がある。`reports/2026-09-22T08-25-04.719Z-public/exploration/step-1.png` では「MENU」が見えるが、対応する `step-1.json` の操作候補は空ラベルとして除外されている。
この取りこぼしが今回の未達すべての原因だとは断定できないが、人が操作できる候補を Jev に渡せていない。
操作候補の取得と探索経路は引き続き修正が必要であり、今回の未達をサイト側の UX 不良や営業の根拠には使えない。
