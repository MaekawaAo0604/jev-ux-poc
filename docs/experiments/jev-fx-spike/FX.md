# USD/JPY の現在値による仮想売買

既存の独立比較エンジンを使い、Jev と固定ルールを同じドル円配信で測定する。
実注文は出さず、取引口座の認証情報も使わない。
この実験は短時間の動作確認であり、収益性の検証には足りない。

## 実行

```powershell
node --test docs/experiments/jev-fx-spike/*.test.mjs
node docs/experiments/jev-fx-spike/fx-probe.mjs --duration-seconds 600
node docs/experiments/jev-fx-spike/audit-comparison.mjs reports/<生成フォルダ>
```

購入制限を外す場合は、次のオプションを使う。
手数料、スプレッド、約定ずれ、数量、空売り禁止は変更しない。

```powershell
node docs/experiments/jev-fx-spike/fx-probe.mjs --duration-seconds 600 --no-entry-cost-filter
node docs/experiments/jev-fx-spike/fx-ablation.mjs reports/<制限ありで測定したフォルダ> --samples 40
```

後者は保存済みの同一入力を使う判断比較で、売買や損益計算は行わない。
要求順から等間隔に 40 件を選び、元の購入条件を通った入力も追加する。
各入力で制限ありとなしの両方を実際に問い合わせ、問い合わせる順序は交互に入れ替える。
通過例を多く含む標本なので、結果の比率を市場全体の売買頻度とは解釈しない。

判断指示だけを比較する場合は、同じコマンドに `--compare-prompts` を加える。

```powershell
node docs/experiments/jev-fx-spike/fx-ablation.mjs reports/<制限ありで測定したフォルダ> --samples 40 --compare-prompts
```

この比較では旧指示・新指示の両方で購入ゲートを外す。
新指示は、観測した値動きと保有状況から費用控除後の各行動を比較し、
不確実性を織り込んで選ぶよう求める。利益の確実性も売買回数の増加も求めない。
価格、費用、数量、元の口座状態は変えず、実際に送った状態と指示のハッシュを記録する。
各入力の口座は未保有のままなので、保有後の売却判断や損益は検証できない。
このオプションは比較専用で、通常の現在値測定の指示は自動では切り替わらない。

600 秒は今回の観測期間で、判断間隔ではない。
価格配信ごとに固定ルールを実行し、Jev の応答待ちでは最新の入力だけを保持する。
Jev の同時要求は 1 件とし、成功後は最新の観測で次の判断を行う。
Jev の一時エラーでは待機して再観測し、3 回連続で失敗したら Jev だけを止める。
その場合は比較未完了と表示する。
初回測定で受け取った HTTP 529 は、修正後は限定的な再試行の対象に含めている。

## 価格と費用

- 価格：GMO コインの [公開 FX API](https://api.coin.z.com/fxdocs/) が配信する `USD_JPY` の bid/ask。
- 数量：公開銘柄情報で確認した最小数量に合わせ、1 回 100 USD。
- 仮想資金：各口座 150,000 JPY。全額を現金で賄う買い方向だけで、空売り、レバレッジ、買い増しは行わない。
- 手数料：[公式 API 取引条件](https://coin.z.com/jp/corp/product/info/fx/api/) の片道 0.002%。無料体験の割引を使わず、約定代金に料率を掛ける。端数処理は再現せず小数で保持する。
- 約定ずれ：片道 0.001 JPY/USD だけ不利な価格を仮定する。実測ではない。

各方式の判断完了後、最初に受信した有効気配で模擬約定する。
買いは ask に約定ずれを加え、売りは bid から引く。
配信には数量がないため、100 USD 全量を約定できると仮定し、板の偏りを Jev に渡さない。
実際の約定可能性、証拠金、ロスカット、税、資金調達費は再現しない。
スワップを計上しないため、配信の有無にかかわらず日本時間 06:00 の境界で測定を止める。

## 比較対象

比較するのは Jev、元の固定ルール、費用条件付き固定ルール、買って保有、現金維持の 5 方式。
資金、保有数量、約定待ちは方式ごとに独立している。
元の固定ルールは、過去 5 秒の仲値変化が正なら未保有時に買い、負なら保有分を売る。
収益性を確認済みの戦略ではない。

Jev と費用条件付き固定ルールでは、過去 5 秒の上昇率が現在の往復費用を超える場合だけ新規購入を許す。
開始直後は取得済みの部分窓を使い、その長さも記録する。
この条件は将来の値上がりを予測しないため、通過後でも損失は出る。
売却はこの条件で制限しない。

Jev の入力時、応答時、模擬約定時には時差がある。
全配信中に条件が通った回数と、Jev が条件通過を実際に見た回数は分けて確認する。
固定ルールと Jev の判断時点は一致しないので、判断能力だけを比較する実験でもない。

## 検算と記録

`reports/jev-usdjpy-paper-<時刻>/` に実行条件、原配信、判断、約定、損益曲線を保存する。
`audit-comparison.mjs` は会計エンジンを取り込まず、固定数量、約定価格、両側の手数料、損益、最大下落幅、購入条件を再計算する。
受信メッセージと気配値を照合し、1 メッセージを複数の気配に使い回した記録も拒否する。

損益は JPY、保有数量は USD で表示する。
既存エンジン内部の変数名には BTC/USD が残るが、専用アダプターが Jev の入力と保存形式を変換する。
金額を換算しているのではなく、単位に合う項目名へ置き換えている。

Jev の実請求額は不明として保持する。
成功した要求のトークン数と実行時に取得した [公開単価](https://ai-gateway.vercel.sh/v1/models) から概算を別記し、終了時の仲値で円相当額を示す。
失敗、中断した要求や実際の換算費用はこの概算に含まない。
売買損益がゼロでも、Jev の利用費までゼロにはならない。
