# Jev と固定ルールの独立比較

公開 BTC/USD の現在の売買気配値（bid/ask）を受け取り、別々の仮想口座で売買する動作検証です。
実注文、空売り、レバレッジはありません。
既存の UX 探索処理からも独立しています。

## 実行

```powershell
node --test docs/experiments/jev-fx-spike/*.test.mjs
node docs/experiments/jev-fx-spike/comparison.mjs --duration-seconds 600
node docs/experiments/jev-fx-spike/audit-comparison.mjs reports/<生成されたフォルダ>
```

600 秒は今回合意した観測期間で、判断間隔ではありません。
正常時の判断タイマーはありません。
30 秒ごとの出力は進捗表示と接続維持のためで、売買判断を起動しません。

実行スクリプトは既存の Gateway キーを実行時のみ読み込み、取引所の認証情報は使いません。
Jev の API 利用には費用がかかり得ます。
利用トークンは記録しますが、実際の利用料が未取得なので損益にゼロとして含めません。

## 独立性

- 共通: 価格配信、特徴量計算、会計処理の実装、手数料と約定条件。
- 個別: 資金、保有、判断回数、判断の開始と完了、約定待ち、停止状態。
- 固定ルール: 価格更新ごとに判断。過去 5 秒の midpoint 変化が正なら未保有時に購入、負なら保有分を売却。それ以外は維持。開始時の部分窓も使用。
- 費用フィルター付き固定ルール: 元の固定ルールと同じ条件で操作を選び、購入時だけ後述のフィルターを適用。
- Jev: API は同時に 1 件。処理中の更新は最新のものだけ残す。キープなら将来の約定価格を待たず、次の更新を判断できる。売買判断は自分の約定だけ待つ。費用情報を入力し、購入時は固定ルールと共通のフィルターもコードで適用。
- 買って保有: 初回から購入を試み、十分な最良気配数量で約定できたら以後保有。数量不足の間は初回価格では約定せず、後続の価格で再判断する。
- 現金: 取引しない参考口座。

Jev の一時エラー時は古い入力を再送せず、復帰後に最新の入力を使います。
回復不能な場合は Jev だけ停止し、固定ルールは観測期間の終わりまで動かします。
その結果は「比較未完了」です。

別 OS プロセスではないため、共通のプロセス、CPU、価格配信、ログが故障したときまで独立して動く設計ではありません。
価格配信の切断、不正データ、ログの保存不能では全体が停止します。
一時的なログ書き込み待ちは順序を保持して解消を待ち、実際の I/O エラーと区別します。
待機データが 4 MiB に達した場合は、メモリを使い続けず全体を停止します。
これは売買回数や判断間隔の制限ではありません。

## 購入フィルター

**購入フィルター**：過去 5 秒の midpoint 上昇幅が、現在の売買費用を超えなければ購入を見送る条件です。
過去の上昇を使うため、将来の値上がりや利益を予測したものではありません。
元の固定ルールと「買って保有」には適用せず、比較対象として残します。

片道手数料率を `f`、片道の不利な約定ずれ率を `s` とすると、購入額を回収するために必要な将来の売却気配を次式で計算します。

```text
breakEvenExitBid = ask × (1 + s) × (1 + f) / ((1 - s) × (1 - f))
requiredRiseBps = (breakEvenExitBid / bid - 1) × 10,000
allowed = observedPastRiseBps > requiredRiseBps
```

現在の ask/bid の差も含むため、スプレッドが広がると必要上昇率は高くなります。
同値は通過させず、観測値がない場合も購入しません。
開始時は取得済みの部分窓を使い、観測期間を記録します。
API 利用料はこの式に含みません。

Jev には入力時点の計算値を渡しますが、返答時には最新の価格で計算し直します。
購入判断が通過しても、模擬約定に使う次の気配でもう一度条件を確認します。
売却には適用しないので、損失中の手仕舞いを妨げません。

各判断には、元の選択 `rawAction`、判断時の適用後 `action`、根拠 `costGate` を残します。
根拠には気配番号、観測済み上昇幅、必要上昇率、損益分岐の売却 bid、見送り理由を含めます。
約定前の見送りは `execution.status = blocked_by_cost_filter` として別に記録します。
判断数と約定数は一致するとは限りません。

## 比較条件と限界

各口座は 1,000 USD、購入額は 100 USD。片道手数料 0.80%、追加の不利な約定ずれ 1 bp を共通の仮定として使います。個人の適用料率や実約定の保証ではありません。

売買は各判断の完了後に受信した最初の有効な気配で試みます。買いは ask、売りは bid。最良気配の数量が不足したらその判断は約定しません。過去の入力価格では約定させず、同じ気配を見て判断しその気配で即時約定する扱いもしません。

最大ドローダウンは全有効気配での仮想清算額から計算します。残りの保有には仮想の売却費用を見込みますが、実際に決済済みの利益とは区別します。板の奥行き、注文待ち順序、最小数量、端数制約、税は十分に再現していません。

固定ルールは比較用の未調整ルールです。これに勝っても、機械的な戦略全般に勝ったことにはなりません。Jev と固定ルールは判断速度も時点も異なるので、これはシステム全体の比較であり、同じ入力時点で判断能力だけを比較した実験ではありません。10 分の結果から収益性は判断できません。

購入フィルターは取引を減らせますが、値上がり後に買って反落する可能性も、取引機会を逃す可能性もあります。
取引ゼロで損失が出なかった結果を、儲かる戦略の証拠にはしません。

## 証跡

`reports/jev-cost-filter-paper-<時刻>/` に以下を残します。
フィルター追加前の `jev-independent-paper-*` は過去の実験として保持します。

- `protocol.json`: 実行前の条件、Jev への指示、コードのハッシュ。
- `events.ndjson`: 生配信、観測値、方式別の判断と約定を記録した追記ログ。
- `results.json`: 損益、手数料、最大ドローダウン、処理時間、利用量、停止状態。
- `index.html`: 損益推移と方式別の比較レポート。
- `audit.json`: 会計コードを再利用しない別スクリプトでの検算結果。購入条件も過去の気配から再計算し、元の判断、見送り、将来気配での再確認を照合。

以前の `live.mjs` は、Jev の判断時点に参考ルールを合わせた元の測定として残しています。独立比較は `comparison.mjs` を使ってください。
