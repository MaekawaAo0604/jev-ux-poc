# 仮想βテスト：既存成果・流用候補・追加調査

確認日：2026-10-27（JST）

[全体像と実装差分](README.md) / [実行用タスク](tasks.md)

## この調査の結論

仮想参加者、ブラウザー操作、変更前後の比較、UX指摘の集約、視野制約、視線予測には、それぞれ先行成果がある。しかし、これらを組み合わせれば対象ユーザーの体験と集団行動を正しく予測できる、とまでは確認できない。

現時点の採用判断は次のとおり。これは実装提案であり、性能確認済みの構成ではない。

| 部品 | 流用・参照候補 | まだ必要な確認 |
|---|---|---|
| ブラウザー実行・ログ | 本リポジトリ、UXAgent | 最新作業版との統合、入力操作、並列実行、ライセンス・依存関係 |
| 注視領域と周辺視の加工 | MODGの実験ハーネス | Web画面への適合、画像縮小の影響、実データによるパラメーター調整 |
| 注視位置・順序 | UEyes、視野制約下の注視学習研究 | 目的・履歴・個人差・動的UIへの対応、重みの実入手性 |
| 個体・集団の生成 | SimGym、AgentA/B | 既存ログがない場合の根拠、属性の組み合わせ、対象集団の代表性 |
| UX問題の集約と修正評価 | UXCascade | 複数ユーザー・複数ステップへの拡張、説明と実観測の区別 |
| 人間との一致の確認 | MODG、選好比較研究、LLM A/B統計研究 | 比較データ、誤差、変更効果、未見UI、予測を保留する条件 |
| 確率的な行動選択 | JevのChoiceと独自サンプラー | 最大確率選択との違い、確率の意味、人間行動への校正 |

**コードが公開されていること、重みやデータが公開されていること、商用製品に組み込めることは別に確認する。** 本調査ではダウンロード・実行・学習・網羅的なライセンス確認はしていない。

## S01. SimGym

原典：[SimGym: A Framework for A/B Test Simulation in E-Commerce with Traffic-Grounded VLM Agents](https://arxiv.org/html/2605.19219v1)（2026-05-19、v1）。

**確認した成果**：実際のクリック履歴から買い物客の特徴と目的を生成し、記憶を持つブラウザーエージェントでストア変更を比較。50店舗、各店舗600エージェントの条件で、カート追加率の変化方向の一致77%、変化量の相関0.55を報告している。

**使う部分**：行動ログに基づくユーザー仕様、セッション記憶、変更による集団の行動差を評価する設計。

**不足・限界**：ECの視覚的なテーマ変更と特定の行動指標の結果。認知・感情・長期継続・新規サービス全体の再現性を示すものではない。公開実装・学習用データの入手性はこの調査では確認していない。

**追加調査**：ログのない段階での個体生成、対象とする行動層の選び方、実行環境、他ドメインへの転用条件。関連：T05、T08、T10。

## S02. AgentA/B

原典：[AgentA/B: Automated and Scalable Web A/B Testing with Interactive LLM Agents](https://arxiv.org/html/2504.09723v2)（参照版：v2）。

**確認した成果**：ペルソナと目的を持つエージェントを用いてWeb上のA/B比較を行う。事例では変更前後に各500体を割り当てている。

**注意する結果**：対照条件の平均操作数は人間15.96、エージェント6.05。人数を増やす仕組みが成立しても、探索の仕方まで一致するわけではない。

**使う部分**：個体生成、実験割当、ブラウザー実行、ログ集計の分解。操作数・検索・商品閲覧等を人間と比較する観点。

**不足・追加調査**：寄り道・迷い・再訪を含む探索の再現、同じ人物の継続性、候補提示やDOMの影響。論文の仕組みと公開コードの対応も確認する。関連：T06〜T09。

## S03. UXCascade

原典：[UXCascade: Scalable Usability Testing with Simulated User Agents](https://arxiv.org/html/2601.15777v2)（2026-08-11、v2）。

**確認した成果**：仮想ユーザーの出力を目的・特性・問題に整理し、UI修正と再評価を支援する。8人のUX専門家による利用評価を報告。

**使う部分**：個別の実行ログから共通問題へ集約する構造、問題から修正候補と再評価へつなぐ導線。

**限界**：本文では、修正後の再評価が単一エージェント・単一ステップに限られると明記。専門家がツールを使えることと、仮想ユーザーが人間を正確に再現することは別。

**追加調査**：全セッションと複数ペルソナの再検証、別集団への悪化検出、実観測に結び付かない説明の除外。公開コードを採用する場合は、著者実装と第三者再実装を区別する。関連：T10。

## S04. UEyes

著者ページ：[UEyes: Understanding Visual Saliency across User Interface Types](https://yuejiang-nj.github.io/Publications/2023CHI_UEyes/project_page/main.html)（CHI 2023）。

**確認した成果**：62人・1,980枚のUIスクリーンショットを対象とする視線データ。Web、デスクトップ、モバイル、ポスターを含む。著者ページにデータ、コード、モデル重みへのリンクがある。

**使う部分**：UI上の視覚的注意の比較データ、初期の視線予測モデル候補。

**限界・確認事項**：この公開概要だけで目的付き連続操作・動的UI・個人差をカバーすると判断しない。著者ページに校正誤差修正の告知があるため、データの版を固定する必要がある。

**追加調査**：取得プロトコル、注視時刻・順序・個人属性の有無、目的条件、校正済みデータと重みの対応、各配布物の利用条件。関連：R01、R02、T04、T07。

## S05. 視野制約下で注視を学習する研究

原典：[Why We Look Where We Look: Emergent Human-like Fixations of a Foveated Visual Language Model Maximizing Scene Understanding](https://arxiv.org/html/2605.17823v1)（2026-05-18、v1）。

**確認した成果**：視野に制約を持たせたモデルを、場面理解の目的で学習すると、人間の自由観察に見られる注視の特徴が現れると報告。

**使う部分**：「何が見えるか」と「理解を進めるために次にどこを見るか」を別々に設計する考え方。

**限界**：主な対象は自由観察の場面理解であり、Web上の目的付き操作全体ではない。

**公開状況**：参照版は、画像・データ・重み・コードを採択後に公開予定としている。現時点で入手可能な完成部品だとは扱わない。

**追加調査**：後続版と実際の公開先、学習データ・計算量、タスク条件付き注意への適用、ライセンス。関連：R01、T04。

## S06. MODG：ぼかした視界でも探索過程は一致するとは限らない

原典：[Matched Outcomes, Divergent Gaze: How Foveated MLLMs Search Compared to Humans](https://arxiv.org/html/2608.16514v1)（2026-08-17、v1）。

著者コード：[kmamine/MODG](https://github.com/kmamine/MODG)。

**確認した成果**：COCO-Search18で、3種類の汎用画像対応モデルを人間に合わせた視野制約下で比較。対象の検出・到達が人間並み以上でも、視線経路の多様性や移動の仕方は一致しなかった。

**使う部分**：注視画像を生成し、次の注視先または探索終了を選ばせる実験ハーネスと評価方法。周辺ブラー・切り取り案をゼロから設計せず比較する候補。

**限界**：自然画像と特定のモデルの結果であり、Web用に学習したモデルまで不可能と示す結果ではない。

**公開状況**：コードとモデル生成出力はMITとREADMEに記載。元画像と人間の視線データはその対象外と明記されている。

**追加調査**：Web画面への移植、画像リサイズの影響、表示距離・視野角への対応、元データの利用条件。関連：T03、T04、T07。

## S07. デザイン選好の人間比較

原典：[Distorted Perspectives of LLM-Simulated Preferences: Can AI Mislead Design?](https://arxiv.org/html/2605.18311v1)（参照版：v1）。

**確認した成果**：29件の実際の選好テスト、2,073人のデータを用い、モデル・サンプリング・ペルソナ条件を変えて比較。実際の選好との系統的なずれが残り、詳細なペルソナ追加が一貫して改善につながるわけではないと報告。

**使う部分**：ペルソナの詳しさや説明文の自然さではなく、実際の選好分布との一致で評価する設計。

**限界**：デザインの選好課題の知見であり、全ての操作シミュレーションへの否定ではない。

**追加調査**：操作・主観評価それぞれに効くユーザー仕様項目、利用可能な元データ、個人内と個人間のばらつき。関連：R04、T05、T07。

## S08. LLMによるA/Bテストの統計的な前提

原典：[Statistical Foundations of LLM-based A/B Testing: A Surrogacy Framework for Human Causal Inference](https://arxiv.org/abs/2606.17165v3)（2026-06-23、v3）。

**確認した成果**：LLMの結果から人間の変更効果を推定できる条件を整理。人間の結果による校正、代理指標としての妥当性、集団間の比較可能性を扱う。

**使う部分**：仮想集団内部での差を、そのまま人間への効果と解釈しないための評価設計。反復生成と、人間を使った妥当性確認を分ける。

**限界**：特定の前提の下での枠組み。校正したことだけで、未知のUIや新しいユーザー層への一般化が保証されるわけではない。

**追加調査**：自分たちの対象での校正方法、前提を反証するテスト、評価単位・信頼区間・必要な人間データ量、長期利用の扱い。関連：T07、T08、T10。

## S09. SimAB

原典：[SimAB: Simulating A/B Tests with Persona-Conditioned AI Agents for Rapid Design Evaluation](https://arxiv.org/html/2603.01024v1)（参照版：v1）。

**確認した成果**：画面とユーザー条件からデザイン案を比較。過去47件のA/Bテストを用い、判定対象45件の混同行列で67%の一致を報告している。

**評価上の注意**：掲載表では45件中28件が変更案の勝ちなので、常に変更案を選ぶ基準は28/45、約62.2%。これは掲載値からの計算であり、論文の追加実験結果ではない。67%だけで十分な性能とは結論しない。

**使う部分**：全画面を直接評価する比較対象、案の提示順を入れ替える設計、未見デザインでの勝敗予測。

**追加調査**：データ分割、保留したケース、既知の公開結果による汚染、強い単純基準との比較。関連：T02、T07。

## S10. UXAgentの公開実装

公開実装：[neuhai/UXAgent](https://github.com/neuhai/UXAgent)。

**確認した内容**：複数エージェントの実験設定UI、参加者条件・タスク等の設定、ログ・セッショントレース・スクリーンショット・集計結果の出力をREADMEで確認。READMEはMITを掲げている。

**使う部分**：実験設定、実行管理、成果物の構成を比較する候補。既存のTypeScript実装を丸ごと置き換えることは前提にしない。Python側の必要部品だけを別プロセスで利用する案も比較する。

**未確認**：この環境での起動、ソース全体の監査、外部モデルやデータを含めた利用条件、現行Jevとの接続。公開されていることを即採用可能と同一視しない。

**追加調査**：固定コミットでの最小起動、依存関係、API境界、既存runnerと重複する機能。関連：R05、T09。

## S11. TypeSafe/Jev公式仕様

公式：[Introduction](https://docs.typesafe.ai/introduction)、[Choice](https://docs.typesafe.ai/primitives/choice)、[ドキュメント索引](https://docs.typesafe.ai/llms.txt)。

**確認した仕様**：Choiceはchoice・probabilities・confidenceを返す。choiceは最大確率の選択肢、probabilitiesは全選択肢に対する分布、confidenceは分布の形から算出する値として説明されている。複数質問は同じstateに対して独立に評価される。

**設計上の意味**：分布を返すことと、その分布から行動をサンプリングすることは別。confidenceを人間の自信や行動頻度と解釈しない。認知状態の更新結果を次の判断に使う場合、同一呼び出し内の独立質問を因果的な連鎖とみなさない。

**追加調査**：実際に利用するモデル・API経路での画像入力形式、制限、座標とリサイズ、Choiceの校正方法。理由説明を取得する場合は、観測証拠やモデル内部の真の理由と同一視しない。関連：R03、T03、T06。

## まだ調査が足りない領域

以下は、この資料で解決済みとはしていない。

- 目的付き・動的なWeb UIの視線データと予測モデル。
- 見たものを理解・記憶する過程、見ても気づかないケース、周辺での変化への反応。
- 感性工学の測定項目と、操作・離脱につながる状態変化の接続。
- 人間の選択頻度に合わせるための確率校正と、未知の条件での誤差。
- 初回利用、学習、再訪問、疲労、時間経過のモデル化。
- 公開前で実ユーザーログがないプロダクトの母集団設定。
- 協調機能や対人相互作用を含むβテストへの拡張。
- 各コード・重み・データの利用条件と再現性。

調査は「関連論文を増やす」ためではなく、[R01〜R06](tasks.md#追加調査のチケット)の採用判断と、T03以降の実装選択を決めるために行う。

## 以前の説明から厳密にした点

- 前提としていた「画像入力版」は、確認したmasterでは確認できていない。最新作業版を特定する。
- 「確率が出る」「多数の個体を動かせる」「人間の分布を予測できる」を分離する。
- ブラー処理のみで人間の探索になるとは扱わない。否定的な比較結果と、注視を学習する成果の両方を参照する。
- 論文の公開予定、コードの実在、起動可能性、利用条件を別の確認項目にする。
- この調査から収益性や現在の販売開始時期は結論しない。今回の出力は、構想実現に必要な不足と作業の整理である。
