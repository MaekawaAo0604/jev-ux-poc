# 探索の動きを、目的達成とは分けて確認する

2026-11-05。目的は、対象ユーザーとしてあり得る探索かを確認すること。未達でも自然な探索はあり、成功しても不自然な動きはあり得る。前の報告で達成率を新方式の採否に結びつけた評価を訂正する。旧3/4・新1/4は参照値として保持するが、人間らしさの順位には使わない。

既存8試行・88判断を事後に再分析した。追加モデル要求0。新旧どちらの人間一致も確認できていない。評価軸は利用者の訂正後に定めたもので、事前登録した自然さ指標や統計検定として扱わない。

## 見る観点

- 同じ画面へ戻る間に、別候補・新情報・期待の変化があるか。
- 前の操作結果が次の入力に残っているか。残っていることと、モデルが使ったことを分ける。
- モデルが選んだ操作と、基盤が補正して実行した操作を分ける。
- 再訪理由が読み取れるか。「2回戻ったら異常」などの閾値は置かない。
- 正解ボタンを押さないこと、未達、短い往復だけを理由に異常としない。

## 1. 基盤の補正が往復を作る例

新方式・図書館r1の後半は、マイページ9 → 利用情報10 → マイページ11 → 利用情報12 → 終端マイページ。9/11、10/12はそれぞれ同じ実入力PNGだった。終端は実操作後の監査状態で、次のモデル観察ではない。

step10のモデル出力は「利用情報を確認する」e1が0.96、「マイページへ」e2が0.04。基盤がe1へ0.01の重みを掛け、補正後はe1が約0.194、e2が約0.806となり、実行は戻るe2になった。step12もモデルはe1を選んだが実行はe2だった。数値はモデル分布であり、人間の自信や行動頻度ではない。

講座予約r2のstep10/12でも、モデルは確認e1、実行は戻るe2だった。この4回の退出を「モデルが前の操作を忘れて戻った」と解釈することはできない。共有の一時保留方針が動作に介入している。

ただし、補正を外した後の全経路は不明である。1手が変われば次の画面と判断も変わるため、保存された後続判断をそのまま無補正の仮想経路へつなげない。

## 2. モデル自身の往復も残る

新方式・講座予約r1のstep9–12もマイページと利用情報を交互に行き来するが、この区間はモデルchoiceと実行が一致する。同じ保存条件の状態確認を選び、condition_uncertainを受け取りながら、同じ画像の間を移動した。前の結果は次の入力へ配送されていた。

ここはモデル側の動きとして確認すべき候補である。移動によって次に何を確かめるつもりかを十分に説明できているか、判断材料が不足している。人間にも短い混乱や確認の往復はあり得るため、この記録だけで非人間的とは断定しない。

## 3. 未達でも自然に説明できる探索

新方式・図書館r1の前半は、確認操作と受付表示 → 予約記録を見る → 変更画面を試す → まだ利用できない画面を見る → 利用情報へ戻る、という順序だった。途中で異なる情報を得ている。別の場所を見ても解決せず、前の確認へ戻る動きとして説明できる。記録画面の照合ボタンを押さなかっただけでは異常にしない。

旧方式・講座予約r2も、変更画面・利用情報・予約記録を見た後、最後に確認操作を再実行した。目的は未達だったが、他の候補を調べてから再訪するという利用者の動きとしてあり得る。これは可能な解釈であって、人間実験との一致を確認したものではない。

## 4. 補正は常に悪いとも限らない

8試行にモデルchoiceと実選択の違いは7件あった（旧2、新5）。そのうち、旧講座予約r2のstep9と新講座予約r1のstep7では、補正が利用情報への再訪を予約記録へ切り替え、別の場所を見る動きを作っていた。7件全てを不具合や不自然さとは呼ばない。補正方針をユーザー再現モデルの一部として扱うなら、その意味と効果を独立に評価する必要がある。

## 履歴と画面の制約

再訪時には、最初の受付完了表示が消えて元の利用情報画面に戻っていた。これは表示上の事実である。再確認したくなる可能性はある。

一方、画像メモリ3だけで履歴全体を判断できない。図書館r1では、受付後に見た「予約記録との照合がまだ完了していません。」という過去引用がstep12の入力にも残った。step10のexperienceには前の確認操作と結果も残る。従って、受付PNGが現在添付されていないことを、完全に忘れた証拠とはしない。

独立担当は6枚の実入力PNGを直接確認し、88件全ての現在画像hashを照合した。直前に受理した結果を次の評価へ引き継ぐ機会72件も照合した。これは配送の確認であり理解の確認ではない。最終結果には次の判断がないため、次評価への引継ぎ欠測として数えない。監査のDOM・隠れたfixture状態は閲覧者の確認用であり、モデルが知っていたことへ置き換えない。
