# Vision restriction implementation and research record

The requested virtual-beta source documents were absent from the baseline checkout. This file records the implementation chosen from the supplied requirements and primary dependency documentation. It does not reconstruct missing research conclusions or claim human validity. No model is trained or fine-tuned.

## Implemented conditions

`jev/virtual-beta/vision.ts` takes PNG bytes, configuration, a fixation in screenshot pixels, and anonymous target rectangles. It has no browser, UI, DOM, network, OCR, or model calls.

- `full` returns an independent copy of the exact input PNG bytes. Source and delivered SHA-256 are equal. Its clear rectangle is the full source image and its transform is identity. The candidate helper preserves baseline labels in this condition.
- `crop` returns an actual newly encoded PNG containing only the clear rectangle. Integer fixation pixels anchor the rectangle. Its intersection with the source bounds shrinks at edges; it never shifts the fixation inward to preserve rectangle size. The image-to-viewport mapping adds the crop origin; there is no resizing.
- `foveated` returns the full source dimensions with the clear rectangle copied exactly and all other pixels replaced by a deterministic box average. Radius `r` means an inclusive square neighborhood from `-r` to `+r`, clipped at source boundaries and divided by its actual in-bounds sample count. Horizontal sums are retained without rounding and the final two-dimensional average is rounded once. All four encoded RGBA channels are processed independently.

The box filter is an experimental degradation operator. It is not a Gaussian filter or a calibrated model of retinal acuity, peripheral crowding, contrast sensitivity, saccades, or reading ability. A fixed rectangular boundary creates a discontinuity. It averages gamma-encoded channels without linear-light or premultiplied-alpha processing. Tests use opaque screenshots. Peripheral content may remain recognizable; this mode makes no promise of information removal. Pixel dimensions are not visual angles, and the chosen clear size or blur radius is a configuration parameter without human calibration.

## Metadata and candidate boundary

`fixation`, `clearRect`, and `visibleTargets` use source screenshot coordinates. `width`/`height` describe the delivered image. `sourceWidth`/`sourceHeight` describe the captured source. `transform` maps image coordinates to source coordinates as `source = image * scale + offset`; current scales are one. `imageToViewport` validates the image point and mapping and rejects out-of-bounds or nonfinite coordinates.

Only control rectangles fully contained in `clearRect` enter `visibleTargets`, including in foveated mode. When the caller supplies an optional badge rectangle, constrained modes additionally require the entire badge inside `clearRect`; a fully visible control with a cropped or peripheral marker is not offered. Validated badge geometry survives through the same explicit geometry whitelist; badge text, connector details, and other runtime fields do not. Full mode retains its previous control-bounds eligibility rule. Partly visible controls and controls outside the viewport are excluded. This is an operational click-eligibility rule, not a claim that humans cannot recognize partly visible controls. The renderer must supply tight source-coordinate bounds. This module cannot establish occlusion or rendered text visibility from a rectangle alone.

Constrained target IDs must be plain decimal numbers or AccountPage's anonymous `eN` format. Target objects are rebuilt from an explicit geometry whitelist so runtime fields such as text, labels, or attributes do not survive. Click candidates must have a matching anonymous key, action ID, and visible target. Their supplied labels are discarded and replaced with the exact anonymous screenshot marker (`e12` becomes `[e12]`). Fixed actions receive generic labels and rebuilt action objects. Their keys must be canonical action names, `scroll_up`/`scroll_down`, or `look_N`/`look_N_N`. Arbitrary source-derived keys and all supplied non-click labels are discarded. Full mode preserves the baseline labels by design.

Candidate IDs refer to the numbering already drawn by the caller. The transformer neither invents new numbering nor changes UI state. Look points are validated source coordinates; executing a look, consuming its budget, and obtaining the next observation are caller responsibilities. The caller must pass only transformed bytes to the model and keep raw screenshots, DOM, audit records, and historical baseline labels out of constrained prompts. PNG hashes and dimensions describe an observation; they do not prove which payload a model received. The runner records the actual payload and saved assets separately.

## Dependencies and primary sources

The repository already pins runtime `pngjs` to `7.0.0` and development declarations `@types/pngjs` to `6.0.5`. This change adds no packages or model assets. The installed `pngjs` package declares Node >=14.19.0 and no runtime dependencies. Its documented synchronous API reads a PNG buffer to RGBA data and writes that data back to a buffer; its PNG pixel-copy API supplies the crop operation. References: [official README and sync API](https://github.com/pngjs/pngjs#sync-api), [official synchronous adapter source](https://github.com/pngjs/pngjs/blob/main/lib/png-sync.js), and [official pixel-copy source](https://github.com/pngjs/pngjs/blob/main/lib/png.js).

The installed `node_modules/pngjs/lib/parser-sync.js` returns a plain decoded metadata/data object. Despite the installed TypeScript declaration's PNG-shaped return type, the synchronous result has no instance `bitblt` method. This implementation therefore uses static `PNG.bitblt(source, destination, ...)`, verified against installed `lib/png.js` and actual crop pixels. Upstream links use the current official main branch because the guessed `v7.0.0` tag URLs were unavailable; installed package files are the version-specific execution evidence.

`pngjs` is MIT licensed. Its installed LICENSE credits Luke Page and original contributors (2015) and Kuba Niegowski (2012); redistribution must preserve its copyright and permission notice. The upstream [license](https://github.com/pngjs/pngjs/blob/main/LICENSE) includes the standard warranty disclaimer. This module calls the existing dependency and does not vendor or modify upstream source. Existing package/license materials must remain with any redistributed dependency bundle. Type declarations stay a development dependency. Hashing uses Node's built-in `node:crypto` SHA-256, with no added hashing package.

## Verification scope

`tests/virtual-beta-vision.test.ts` decodes delivered PNGs to inspect real pixels and covers exact full bytes/hash preservation, crop size/origin/pixels, edge intersections, odd and oversized clear windows, coordinate mapping, actual peripheral blur and clear preservation, deterministic encoding, visible-target filtering, secret-label and extra-field exclusion, anonymous eN marker mapping, badge-boundary eligibility and badge-field sanitization, arbitrary-key rejection, and malformed configurations/coordinates/targets. These checks establish the implementation's data boundary and pixel behavior. They do not establish equivalence to a human observer, cognition, task performance, or elapsed human time.
